# Melhorar Onboarding E First Run

## Status

`planejado`

## Objetivo

Reduzir friccao no primeiro uso do app, com CTAs mais claros, empty states mais orientativos e melhor conducao do usuario sem dados.

## Contexto

Os docs de launch readiness indicam que o nucleo do produto ja existe, mas ainda falta validar se a experiencia inicial guia bem o usuario a cadastrar o primeiro veiculo, manutencao ou abastecimento.

## Escopo

- [ ] revisar empty states principais
- [ ] reforcar CTA para primeiro veiculo
- [ ] reforcar CTA para primeira manutencao e primeiro abastecimento
- [ ] revisar textos de telas sem dados
- [ ] revisar mensagens de sucesso e erro em fluxos principais

## Fora De Escopo

- onboarding tutorial longo em multiplas etapas
- carrosseis ou tours complexos
- reformulacao visual ampla do produto inteiro

## Regras De Negocio

- o usuario deve entender rapidamente o proximo passo util
- empty state deve explicar valor, nao apenas ausencia de dados
- melhorias devem preservar simplicidade e nao atrapalhar quem ja conhece o produto

## Mudancas Tecnicas Esperadas

- revisar dashboard, vehicles, maintenances, fuel e profile
- revisar componentes de empty state e feedbacks de acao
- possivel criacao de CTAs mais padronizados

## Checklist De Implementacao

- [ ] mapear telas principais de primeiro uso
- [ ] revisar copy atual e pontos de confusao
- [ ] ajustar empty states e CTAs
- [ ] revisar fluxos de sucesso/erro mais importantes
- [ ] validar em mobile

## Checklist De Validacao

- [ ] usuario novo entende que precisa cadastrar primeiro veiculo
- [ ] usuario novo encontra caminho para primeira manutencao
- [ ] usuario novo entende quando ainda nao ha dados suficientes no dashboard
- [ ] feedbacks de sucesso e erro ficam claros

## Dependencias

- avaliacao de UX real ou smoke test manual
- componentes atuais de empty state

## Observacoes

Esse item e importante para reduzir abandono no lancamento inicial mesmo sem adicionar feature nova.
